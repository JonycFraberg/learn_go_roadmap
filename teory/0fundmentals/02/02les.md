## Лекция 2. Командная оболочка

```bash
touch folder/{a,b,c}.py
# Эквивалентно следующей команде:
touch folder/a.py folder/b.py folder/c.py
```

### Подсказка по Vim

![Шпаргалка по клавишам Vim](image.png)

### 1. Основы CLI и аргументы

В отличие от языков программирования общего назначения, командная оболочка ориентирована на запуск программ и организацию их взаимодействия.

**Специальные переменные:**

$0 — имя скрипта.
$1...$9 — аргументы по порядку.
$@ — все аргументы сразу (списком).
$# — количество аргументов.
$? — код возврата последней команды (0 = успех, остальное = ошибка).


**Глоббинг (globbing)** — раскрытие шаблонов путей командной оболочкой.

* — любое количество символов.
? — ровно один символ.
`{}` — brace expansion (не глоббинг). Например, `touch {src,bin,test}/main.go` обращается сразу к трём путям, но каталоги должны быть созданы заранее.


### 2. Потоки и перенаправление

Программы в конвейере (`|`) работают одновременно: стандартный вывод одной программы поступает на стандартный ввод следующей.

**Стандартные потоки:**

stdin (0): Входной поток.
stdout (1): Стандартный вывод.
stderr (2): Вывод ошибок.


**Перенаправление:**

> — перезаписать файл.
>> — дописать в конец.
2> errors.txt — только ошибки в файл.
&> all.txt — и вывод, и ошибки в один файл.
cmd < input.txt — подать содержимое файла на вход программе.


**Подстановка процесса (process substitution):** `<(command)` позволяет представить вывод команды как путь к временному файловому дескриптору. Пример: `diff <(ls folder1) <(ls folder2)`.

### 3. Переменные окружения

Синтаксис: `NAME=VALUE` (без пробелов вокруг `=`).

**Кавычки:**

' ' (одинарные) — буквальная строка, переменные внутри НЕ раскрываются.
" " (двойные) — переменные (например, $USER) будут заменены значениями.


- `export VAR=value` делает переменную доступной дочерним процессам, например Go-программам;
- `PATH` содержит список каталогов, в которых оболочка ищет исполняемые файлы.

### 4. Сигналы и управление задачами

Сигналы — механизм уведомления процессов о событиях.

- `Ctrl+C` (`SIGINT`) — запросить прерывание программы;
- `Ctrl+\` (`SIGQUIT`) — запросить завершение с дампом памяти;
- `Ctrl+Z` (`SIGTSTP`) — приостановить процесс.

**Управление фоновыми задачами:**

jobs — список задач.
fg %1 — вернуть задачу №1 на передний план.
bg %1 — продолжить выполнение задачи №1 в фоне.
& в конце команды (например, sleep 100 &) — запустить сразу в фоне.
nohup — запуск программы так, чтобы она не закрылась при выходе из терминала (SIGHUP).


### 5. Удалённая работа по SSH

Файл `~/.ssh/config` позволяет задавать короткие имена для подключений:

```sshconfig
Host my-server
    HostName 1.2.3.4
    User root
    IdentityFile ~/.ssh/id_ed25519
```

После этого вместо длинной строки пишешь просто ssh my-server.
Копирование: scp (простое) или rsync (умное, докачивает только изменения).

```bash
ssh-keygen -a 100 -t ed25519 -f ~/.ssh/id_ed25519
```

### 6. Терминальный мультиплексор tmux

`tmux` позволяет сохранять терминальную сессию при разрыве соединения.

Иерархия: **сессии → окна → панели**. Префикс по умолчанию — `Ctrl+B`.

Ctrl-b % — вертикальный сплит.
Ctrl-b " — горизонтальный сплит.
Ctrl-b d — отключиться от сессии (сессия живет в фоне).
tmux a — вернуться в последнюю сессию.


### 7. Настройка окружения (dotfiles)
Aliases: Сокращения. Например: alias gs="git status".
Функции: Для более сложной логики (где нужны аргументы внутри).
Frameworks: oh-my-zsh, prezto — делают терминал красивым и умным, но могут замедлять запуск.
Полезные утилиты:

fzf — нечеткий поиск по истории и файлам.
tldr — краткие примеры команд вместо бесконечных man.
ripgrep (rg) — современная и быстрая замена grep.

## Лекция 4: Debugging and Profiling

🛠 Отладка и Профилирование (Главное)1. Отладка (Как найти баг)
Логирование: Вместо обычного fmt.Println используй уровни (DEBUG, INFO, ERROR). Это помогает фильтровать мусор.
Отладчики (GDB/Delve): Позволяют остановить программу на любой строке и посмотреть, что лежит в переменных.
strace: Показывает, какие файлы программа открывает и что просит у системы (если программа «висит», strace покажет, на чем именно).
Инструменты:

strace — слежка за системными вызовами.
tcpdump — слежка за сетевыми запросами.


2. Профилирование (Как ускорить)
Тайминг: Команда time показывает, сколько реально работал процессор, а сколько программа просто ждала (например, ответа от сети).
Мониторинг:

htop / btop — что сейчас ест память и CPU.
lsof — какие файлы открыты процессом.


Профилировщики (perf): Рисуют Flame Graphs (огненные графики), где сразу видно самую «горячую» функцию, которая тормозит всё.
Бенчмаркинг: Инструмент hyperfine — позволяет точно сравнить, какая из двух команд работает быстрее.

💡 Шпаргалка: что выбрать?
Программа упала? — Debugger / Logs.
Программа работает медленно? — Profiler / htop.
Программа ведет себя странно с файлами или сетью? — strace.

### Практика: Command Challenge

Цель: решить 20 задач на [cmdchallenge.com](https://cmdchallenge.com/).

#### 1. Вывести `hello world`

```bash
echo "hello world"
```

#### 2. Вывести текущий рабочий каталог

```bash
pwd
```

#### 3. Вывести имена файлов по одному в строке

```bash
ls -1
```

#### 4. Вывести содержимое `access.log`

```bash
cat access.log
```

#### 5. Вывести последние пять строк `access.log`

```bash
tail -n 5 access.log
```

#### 6. Создать пустой файл

```bash
touch take-the-command-challenge
```

#### 7. Создать вложенные каталоги

```bash
mkdir -p tmp/files
```

Флаг `-p` создаёт отсутствующие родительские каталоги и не возвращает ошибку, если каталог уже существует.

#### 8. Скопировать файл

```bash
cp take-the-command-challenge tmp/files/
```

#### 9. Переместить файл

```bash
mv take-the-command-challenge tmp/files/
```

#### 10. Создать символическую ссылку

```bash
ln -s tmp/files/take-the-command-challenge take-the-command-challenge
```

#### 11. Удалить всё содержимое каталога

Включая скрытые файлы и вложенные каталоги:

```bash
rm -rf -- * .[!.]* ..?*
```

> **Осторожно:** `rm -rf` удаляет данные без подтверждения. Перед выполнением нужно убедиться, что текущий каталог выбран правильно.

#### 12. Рекурсивно удалить файлы `.doc`

```bash
find . -type f -name "*.doc" -delete
```

#### 13. Найти строки с `GET`

```bash
grep "GET" access.log
```

#### 14. Найти имена файлов, содержащих `500`

```bash
grep -l "500" ./*
```

#### 15. Найти относительные пути по шаблону

```bash
find . -type f -name "access.log*"
```

Шаблон заключён в кавычки, чтобы его обрабатывала команда `find`, а не оболочка.

#### 16. Вывести совпавшие строки без имён файлов

```bash
grep -r -h "500" --include="access.log*" .
```

- `-r` — рекурсивный поиск;
- `-h` — не выводить имена файлов;
- `--include` — искать только в файлах, соответствующих шаблону.

#### 17. Извлечь IP-адреса

```bash
grep -r -h -oE '[0-9]+(\.[0-9]+){3}' --include="access.log*" .
```

- `-o` выводит только совпавшую часть строки;
- `-E` включает расширенные регулярные выражения;
- `[0-9]+` означает одну или несколько цифр.

> Этот шаблон проверяет только форму адреса и может совпасть с числами вне диапазона `0–255`.

1. Цепочка команд для завершения процессовps aux | grep go | awk '{print \$2}' | xargs kill
Что делает: Находит и принудительно завершает все процессы, в названии которых есть слово "go".
Шаги: ps (список) → grep (фильтр по имени) → awk (выбор PID) → kill (завершение).
2. Перенаправление потоков
>: Перезапись файла (старое удаляется).
>>: Дозапись в конец файла (старое сохраняется).
2>&1: Направляет ошибки (stderr) в тот же поток, что и обычный вывод (stdout). Обычно используется, чтобы записать и ошибки, и логи в один файл.
3. Топ-10 больших файловbash Copy Codedu -ah . | sort -rh | head -n 10

du -ah: Считает размер всех файлов в "человеческом" виде (Мб, Гб).
sort -rh: Сортирует по размеру от большего к меньшему.
head -n 10: Оставляет первые 10 строк.
