# Git: Краткий конспект (Data Model & CLI)

### 🧠 Модель данных (Как Git видит проект)
Вместо того чтобы просто следить за изменениями строк, Git оперирует снимками (**snapshots**).

*   **Blob** (объект): Содержимое файла (просто набор байтов).
*   **Tree** (дерево): Каталог. Связывает имена файлов с их содержимым (blobs) или другими деревьями.
*   **Commit** (снимок): Снимок верхнего уровня + метаданные (автор, дата, сообщение, ссылка на родителя).
*   **SHA-1 Hash**: Уникальный ID объекта. Все в Git адресуется через хеш содержимого. Если файл не изменился, его хеш и объект в базе остаются прежними.

### 📍 Ссылки (References)
*   **Branches**: Подвижные ярлыки, указывающие на последний коммит ветки (например, `main`).
*   **HEAD**: Специальный указатель на то, где вы находитесь в данный момент (на какой ветке или коммите).

### 🛠 Жизненный цикл изменений
1.  **Working Directory**: Файлы, которые вы редактируете сейчас.
2.  **Staging Area (Index)**: «Черновик» или область подготовки. Сюда файлы попадают после `git add`.
3.  **Commit**: Постоянная фиксация состояния из Staging Area в историю (DAG).

### 💻 Основные команды

| Команда | Описание |
| :--- | :--- |
| `git init` | Создать новый репозиторий (папка `.git`). |
| `git status` | Показать текущее состояние (изменено/подготовлено). |
| `git add <file>` | Переместить изменения в Staging Area. |
| `git commit -m "msg"` | Создать новый коммит. |
| `git log --all --graph` | Показать историю в виде графа (DAG). |
| `git checkout <id/branch>` | Перейти к конкретному коммиту или ветке. |
| `git diff <file>` | Показать разницу между рабочей папкой и индексом. |

### 🌍 Удаленная работа (Remotes)
*   **`git remote add <name> <url>`**: Привязать удаленный репозиторий.
*   **`git push <remote> <branch>`**: Отправить свои коммиты в облако.
*   **`git fetch`**: Забрать данные с сервера (без слияния).
*   **`git pull`**: Забрать данные и сразу слить их в свою ветку (`fetch` + `merge`).
*   **`git clone`**: Скопировать удаленный репозиторий целиком.

---

### 💡 Главный совет
Git — это **направленный ациклический граф (DAG)**. Любая команда — это манипуляция с этим графом: добавление узла (commit), передвижение указателя (branch) или переключение фокуса (checkout).
